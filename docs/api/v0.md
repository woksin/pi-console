# Mock daemon API v0

> Historical M0 spike contract only, including the legacy query-token/cookie exchange below. The current daemon
> and testkit mock use [API v1](v1.md#security): bearer headers only, with no query-token or cookie authentication.

M0 contract shared by the web and TUI spikes. Node 26 runs erasable TypeScript
without a build step or dependencies. From the repository root:

```sh
node spikes/fixture/generate.ts
node spikes/mock-daemon/server.ts --port 4777 --speed 1
# Optional transcript stress: --rate 5000 (entries/second)
TOKEN=$(cat .pi-console-dev/token)
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:4777/api/v0/overview
curl -N -H "Authorization: Bearer $TOKEN" http://127.0.0.1:4777/api/v0/stream
```

`--port` is an integer 1–65535 (default 4777); `--speed` is a positive timeline
multiplier (default 1); `--rate` is a positive integer overriding only transcript
cadence, independently of speed. All data and text are synthetic. Never point
this mock at real session files. It binds **127.0.0.1 only**.

## Security

The daemon creates a random 256-bit hex token at `.pi-console-dev/token` (0600),
inside an owner-only directory (0700). It compares credentials in constant time.
Every request requires `Authorization: Bearer <token>` or the login cookie.
Only Host `127.0.0.1:<actualPort>` and `localhost:<actualPort>` are accepted.
No forwarded headers, remote access or CORS grants are supported.

Browser bootstrap: GET any API URL with `?token=<token>` returns **303**, sets
`piConsoleToken=<token>; HttpOnly; SameSite=Strict; Path=/api/v0`, and redirects
to the same relative URL with the token removed. This exchange does not return
the requested JSON/SSE body. Do not share URLs containing the token. Cookies are
not Secure because the mock serves loopback HTTP only.

A supplied Origin must be exactly `http://127.0.0.1:<port>` or
`http://localhost:<port>`; a foreign Origin is refused, including on SSE.
`Sec-Fetch-Site: cross-site` is always refused. **POST and SSE without Origin
require a bearer token, never cookie alone.** Cookie-authenticated POST also
requires `X-Pi-Console-CSRF: 1` and an allowed Origin. Bearer-only command-line
clients need no CSRF header. Authentication is checked on each connection.
Token rotation/revocation is not implemented: stop the daemon, replace/remove
the token file, then restart (closing all streams). The single development
credential grants read and mock-control scope; no command is actually delivered.

## Representations and schemas

JSON uses camelCase, string ids, RFC3339 timestamps, explicit nullable fields and
arrays (including empty ones). Cursors and sequence numbers are nonnegative safe
integers, not ids. Monetary values are synthetic USD. Entity ids are stable
within the fixture; lane ids are scoped by repository. Relationships use session
ids, not ambiguous lane ids. HTTP JSON responses use `application/json` and
`Cache-Control: no-store`. There is no implicit success envelope.

[`schemas/api.json`](schemas/api.json) is JSON Schema draft 2020-12. Each
response and SSE payload has a named `$defs` entry; the table below identifies
which one. `event` discriminates SSE envelopes by their exact `type`.
[`schemas/intervention-input.json`](schemas/intervention-input.json) references
the input definition. Schemas are generated alongside the recordings by
`spikes/fixture/generate.ts`; commit generated files together. The stdlib test
validator implements exactly the schema keywords used here, not arbitrary JSON
Schema. It enforces formats, required fields, enums, bounds and extra fields.

## HTTP queries

All paths below have prefix `/api/v0`. Successful GETs return **200**.

| Method/path | Response `$defs` | Meaning |
| --- | --- | --- |
| GET `/overview` | `overview` | Session/repository counts, counts by status, needs-you items, aggregate 24-point token/cost/context sparkline |
| GET `/sessions` | `sessions` | `{items: Session[]}`; all 30 sessions, including nested workers |
| GET `/sessions/:id` | `sessionDetail` | `{session, requests, questions, jobs, resets, subagents}` |
| GET `/sessions/:id/transcript?after=0&limit=100` | `transcript` | `{items, nextCursor, hasMore}` in ascending cursor order |
| GET `/requests?filter=all` | `requests` | `{items}`; filter `all`, `unanswered`, or `interrupted` |
| GET `/questions` | `questions` | `{items}` with kind, urgency, options, blocking and asker session |
| GET `/messages` | `messages` | `{items}` with sender/recipient session ids and sent/delivered/read state |
| GET `/jobs` | `jobs` | `{items}` with kind `job`, `phase`, or `ci`, state and exit code |
| GET `/stream` | `event` | Authenticated `text/event-stream`; see below |

Transcript `after` is exclusive (default 0); `limit` is 1–1000 (default 100).
`nextCursor` is the last returned cursor, or `after` for an empty page. Cursors
are per-session; only s2 has a recorded transcript. These are M0 mock semantics; production v1 uses sparse
source-byte cursors and checkpoint-backed on-demand history (see [v1.md](v1.md)). The mock retains the latest
5,000 transcript entries. If `after` predates retained entries, the page starts
at the oldest retained cursor; gaps are observable, not a claim of full history.
Unknown sessions return 404. Unanswered filtering matches status `unanswered`
only; open and interrupted requests are available in `all`. Request `origin`
`launch` is labelled **Initial prompt**, and `unproven` is labelled **Unproven
origin**; neither is presented as the human's words. `originEvidence` explains
the classification. An interrupted request has no final answer; its partial
answer and reset link are retained separately.

## SSE: snapshot, deltas, resume

Each frame has this form (the example omits the full session payload):

```text
id: 42
event: session.updated
data: {"seq":42,"type":"session.updated","occurredAt":"2026-11-20T09:00:00.000Z","payload":{...}}

```

`id` equals envelope `seq`. On a new connection, `snapshot` carries the current
read models, reset markers, intervention audit and per-session transcript
cursors (load transcript separately). Its id is the current global sequence,
initially 0. Snapshot delivery does not append a global event. Subsequent deltas
have strictly increasing contiguous ids per connection. `occurredAt` is the
mock emission time; entity timestamps retain the original recorded fixture time.

| Event type | Payload `$defs` | Application |
| --- | --- | --- |
| `snapshot` | `snapshot` | Replace read models; fetch transcript using cursor pagination |
| `session.updated` | `session` | Upsert whole session by id |
| `transcript.appended` | `transcriptEntry` | Append by session/cursor; entries include user, assistant text/deltas, thinking, tool call/result, diff, reset |
| `request.observed`, `request.interrupted` | `request` | Upsert whole request, preserving origin evidence and partial answers |
| `question.asked` | `question` | Upsert whole question |
| `message.sent` | `message` | Upsert message and update graph edge |
| `job.updated`, `job.finished` | `job` | Upsert whole work item |
| `reset.occurred` | `reset` | Upsert boundary with carried/interrupted request ids |
| `intervention.recorded` | `intervention` | Append echoed audit; **not** a delivery receipt |

These are the exact v0 event names; future `request.*`, `question.*` and `job.*`
variants require an additive contract update. SSE names are transport projection
names, not the persisted event catalogue's PascalCase envelopes.

The process keeps the last **10,000 deltas**. Reconnect with
`Last-Event-ID: <seq>` to replay all retained deltas strictly after that id,
then follow live events without a new snapshot. If the id predates the replay
window, receive a fresh snapshot at the current seq instead. Noninteger,
negative, unsafe or future ids return 400 before streaming. Sequence numbers
are process-local: after restart, reconnect without the old id. Heartbeats are
`: heartbeat` comments every 15 seconds, not events. Consumers whose pending
socket output exceeds 1 MiB are disconnected; resume from the last parsed id.

The fixture is already a complete initial read model with a 2,000-entry
transcript. Its relative-`t` JSONL timeline then loops every ~361 seconds at
speed 1. Transcript cadence is one entry per 180 ms by default; loops assign
fresh transcript ids/cursors while other entities are upserted under stable ids.
Repeated reset/message markers intentionally replay the same synthetic scenario.
The mock is not a production event log and does not resolve questions or run
agents. State, replay history and audit disappear on restart.

## POST `/interventions`

`Content-Type: application/json`; body limit 64 KiB. Input schema:
`interventionInput`. Required: `type`, `sessionId`. Types:

- `answer`: nonempty `text` plus `questionId` belonging to that session.
- `steer`, `followUp`, `nextTurn`: nonempty `text` (maximum 10,000 characters).
- `abort`: `confirmation` must equal the target session's lane id; text optional.

Optional `questionId`, when supplied, must belong to the target session. Extra
fields and unknown types are rejected. Maximum 60 accepted interventions per
rolling minute per development credential. All variants return **202** with an
`intervention` audit record and append the identical record as
`intervention.recorded`. Audit fields include id, type, sessionId, nullable
questionId/confirmation, text, actor `user:dev`, tokenId `dev`, origin (or
`bearer`), recordedAt and result `mock-only`. No session status, question or
request is modified, and there is no actual delivery or destructive action.

## Errors and checks

Non-SSE errors are `{ "error": "..." }` (`error` schema): 400 invalid input,
401 missing/invalid credentials, 403 Host/Origin/CSRF rejection, 404 missing
resource, 405 unsupported method, 413 body too large, 415 wrong content type,
429 intervention rate limit, 500 internal error (details withheld). Login 303
and streaming 200 are the only non-JSON response forms.

`npm test` runs fixture byte-determinism, recorded and live schema conformance,
all routes and intervention variants, browser/bearer security, SSE resume and a
5,000-entry/s stress smoke check. `npm run check` checks all spike TypeScript
with Node's parser, parses committed JSON/JSONL, and checks whitespace. No
compiler, external formatter, integration services or build artifacts are needed.
